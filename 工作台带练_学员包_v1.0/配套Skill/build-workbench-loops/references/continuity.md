# 连续工作与版本记录

用于跨会话推进、多次迭代或需求较多的工作台。优先沿用项目已有状态文件；缺失时可建立`WORKBENCH_STATE.md`和`WORKBENCH_VERSIONS.md`。不要求额外数据库，不强制用户填写后台字段。

## 当前状态应回答

- 业务目标、使用者和已确认范围是什么？
- 已有资料、当前入口和最近决定在哪里？
- 当前最重要的不确定性是什么？处于哪个验证循环？
- 哪些能力真实可用，哪些仅是Demo，哪些失败或未知？
- 本版优先验证什么，暂缓哪些需求？
- 最近反馈改变了什么；下一步动作、完成依据和确需用户补充的问题是什么？

记录事实、用户决定、推断和候选方案的区别。引用文件或测试记录，不重复复制全部原始材料。新结论说明替代哪条旧理解。

## 版本记录建议

每版记录日期、用途、主要验证问题、交付入口、包含/暂缓项、实际验证、已知限制、用户反馈与下一步。小修改可以归到同一版，不为每句话制造新版本。

记录工作台如何演进，同时按实际业务需要管理内部资产的版本和配套；两者不混用。

## 变更Skill时

1. 指出实际发生的卡点和证据。
2. 判断是项目知识不足、能力未实现，还是Skill路由/交互有问题。
3. 前两类优先修项目和实现；只有第三类修改通用指令。
4. 用触发该问题的任务重新验证，保留未验证部分。

例如在多课程备课中，课程体系、授课期次、讲师模块和文件版本混淆，优先补项目归类；通用Skill只保留“业务身份与文件版本分开、以证据核对”的原则，不强制所有行业使用课程字段。
