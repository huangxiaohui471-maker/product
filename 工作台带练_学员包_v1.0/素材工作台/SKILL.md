# 素材工作台

本包已有前台、文件存储和内容飞轮三负责人的执行脚本。先读取项目状态，不重建同样的功能。网页不会自己调用模型；当前宿主Agent负责语义理解、判断和内容生成，通过 `agent_bridge.py` 把真实结果接回页面。等待Agent时如实显示等待，不声称后台正在自动生成。

## 当前产品定位（优先于底层引擎的自动飞轮要求）

这部分课先教把已有工作和成果组织成工作台。页面按素材、内容、数据与报告、业务资料来组织，可以任意进入、查找和操作。用户查看、保存数据或得到一份分析报告，这件工作就可以结束；不要求启动新一轮内容制作。

底层保留的飞轮交接能力用于之后明确要求联动的任务，不在当前前台展示“下一轮”入口、不自动从复盘派生生产任务。工作台搭建的三个迭代循环，是开发与校正工作台的方法，也不是学员业务必须按轮次运行的规定。

## 页面设计与改造原则

先判断人是在浏览选择，还是深入查看、编辑或对比。素材、作品、数据与报告默认显示库或列表，点击后进入具体对象；参考和旧版按需打开，不默认展示第一条或固定多栏。返回保留筛选、选择、浏览位置和草稿。手机端打开对照要让用户立即到达内容，并能回正文。不把后台执行过程做成用户必须经过的阶段。

本版视觉采用苹果式浅色工具界面，保留四区侧栏结构。浅灰底、白内容区、深灰字，蓝色用于操作与选中；业务原片保留本色。

补数据、上传和纠正必须带上当前作品的平台、ID和标题；保留版本与原始数据。旧草稿遇到新版本时先对照，用户明确选择基线后才保存；保存期间的新输入不能清除。业务特定标准仍由原三岗Skill和实际企业证据提供。

## 进入已有项目

从用户已经打开的项目承接 `.content-flywheel`；未建立时先读取授权范围内的业务资料，形成简短的业务理解供纠正。不要默认沿用讲师企业。启动：

```bash
python3 server.py --project 项目路径
python3 agent_bridge.py --project 项目路径 pending
```

先用现成工作台让用户看见与校正，保留素材来源、版本和结果。用户要改造业务时沿“看见并校正→跑通并验证→使用并改进”，每轮用具体结果讨论；后台五项检查不是用户问卷。

## 处理页面请求

先运行 `pending`，读取这一项的企业背景、素材证据、旧版和真实反馈。选择一项有条件完成的任务，执行后才提交完成。用户直接在对话提出同类要求时也可创建或承接同一请求，避免两边重复工作。

- 搜索、下载、拆解：读取 `engine/operate-content-strategy-lead/SKILL.md`，复用其连接器、去重、原片和关键帧、拆解与企业适配流程。外部来源权限与费用沿当前授权；已有素材可以先使用。公开内容、供应商投放信号和实际投放结果保持分开。具体命令见 [运行接续](references/agent-actions.md)。
- 生产或修改：读取 `engine/operate-content-production-lead/SKILL.md`；依据当前策略、企业事实和反馈做完整可用内容。不要凭空编造案例、成交额、客户评价；缺证据就换成可支持的表达。通过桥接保存新版本，旧版采用与结果不迁移。
- 数据整理（`growth_data`）：沿原增长负责人的底账结构接收账号资料、导出、截图与反馈。整理、保留来源并显示数据即可完成；不要求生成复盘或行动计划。格式见 [数据与分析接续](references/growth-actions.md)。
- 账号与内容复盘（`growth_review`）：读取 `engine/operate-content-growth-lead/SKILL.md` 和 [增长接续协议](references/growth-actions.md)。承接账号、导出、截图、评论、历史作品或本轮作品，不要求先在此工作台生产并采用。AI 整理事实、比较内容并给出可阅读的分析报告；用户可以查看、补充或纠正。报告不必包含行动计划。旧报告可继承依据，过强归因仍须校正。不得把观察、原因和下一步做成用户必填问卷。
- 用户另行明确要求联动或开展后续制作时（后台 `next_cycle`）：读取 `engine/operate-content-strategy-lead/SKILL.md`，承接 `growth_to_strategy/v1` 的保持项、改变项和证据，重新形成方向和 `strategy_to_production/v1`。完成交接后系统建立新生产任务，由生产负责人制作。不能提交一段新稿就算下一轮完成，也不能把历史账号复盘假装成本轮新稿的市场结果。纯文字润色才使用原任务的 `revision`。
- 业务纠正：更新共同底稿和适配判断。原素材仍保留；旧业务下的推荐需逐条重审或降为待判断。事实不充分时提出一个具体缺口，不能自动把讲师业务替换成新业务名后继续采用。

通过 `agent_bridge.py complete` 提交实际产物，再在浏览器刷新、检查用户可见结果。桥接验证文件/版本，不代替专业判断；不得把“有文件”当成质量已达标。

## 交付边界

保留一个可打开入口和真实项目。先告诉用户已经得到什么、现在只需看哪一处。无需让用户学习脚本、内部ID或JSON。前台必须能回看原片、拆解和判断依据；不能为了简洁只留下热度卡片。

参考视频仅用于分析，改编要基于本企业事实；不自动发布。运行凭据使用现有用户级配置，不写进项目或分发包。讲师私有样例不默认作为学员资料传播。
