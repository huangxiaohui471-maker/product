## A · 为什么做

### A.1 业务背景

当前选品工作依赖人工在多个平台（抖音罗盘、蝉妈妈、FastMoss、Hwahae 等）反复切换查看数据，问题：

1. **数据分散**：同一商品的销量、成分、用户评价、达人带货分散在不同平台，难以横向比较
2. **无法算增量**：罗盘只给近 30 天快照，没有环比趋势，看不到「突然增量」
3. **视频拆解效率低**：想拆一个爆款视频，要先在罗盘找榜、再去蝉妈妈查销售来源、再手动判断是否值得拆
4. **成分分析依赖人工**：看到成分词要去详情页手动找，没有自动聚合
5. **用户画像割裂**：蝉妈妈的受众画像无法跟销量榜单联动

### A.2 目标与成功指标

| 指标            | 现状            | 目标        | 测量方式        |
| ------------- | ------------- | --------- | ----------- |
| 完成一次完整选品评估的时间 | 约 2-3 小时（跨平台） | < 30 分钟   | 用户自述 + 操作录屏 |
| 榜单增量可见性       | 看不到           | 能看到环比增速   | 榜单字段含「环比增速」 |
| 视频拆解决策时间      | 靠经验判断         | < 1 分钟出结论 | 销售来源自动出占比   |
| 成分聚合覆盖率       | 0%            | ≥ 70%     | 标题/详情页文本覆盖  |

### A.3 不做会怎样

- 继续靠人肉在多个平台间来回切换，每天浪费 1-2 小时
- 错过「突然增量」的早期信号，跟品慢一步
- 视频拆解靠直觉，容易把资源浪费在「直播带货型」商品上
- 成分研究效率低，跟品决策缺乏数据支撑

## B · 给谁用

### B.1 目标用户与角色

| 角色            | 职责            | 核心诉求             |
| ------------- | ------------- | ---------------- |
| **选品负责人**（惠子） | 最终决策是否做某个品    | 一屏看到全貌，快速判断是否值得做 |
| **数据分析师**（对方） | 拉数据、清洗、入库     | 数据源接入稳定，字段口径统一   |
| **内容研究员**（对方） | 拆视频、看用户画像、做洞察 | 视频/画像/评论洞察一站式    |

### B.2 使用场景

| 场景     | 触发       | 期望动作                     |
| ------ | -------- | ------------------------ |
| 每日巡盘   | 上班后      | 打开「全球看板」看昨日增量、突然增量       |
| 选品评估   | 看到一个潜力商品 | 在「新品选品台」查它的成分、口碑、销量、关联达人 |
| 视频拆解决策 | 看到一个上榜商品 | 查它的销售来源占比，决定是否值得拆视频      |
| 用户调研   | 要做一个新品   | 查蝉妈妈受众画像 + 评论洞察          |
| 复盘     | 每周末      | 看「复盘页」回顾本周数据             |

### B.3 范围边界

**本期做**：

- 榜单数据接入（抖音罗盘 + 蝉妈妈 + FastMoss + TikHub）
- 成分库（已有，继续完善）
- 用户画像（蝉妈妈）
- 销售来源分析（蝉妈妈）
- 评论洞察（天猫 + 抖音）
- 全球看板 + 新品选品台 + 美妆情报台 + 同行雷达 4 个主页面

**本期不做**（明确拒绝）：

- ❌ 视频拆解模块（AI 视频分析）—— 需求存在但本期不做，先人工拆
- ❌ 用户调研模块（AI 问卷/访谈）—— 需求存在但本期不做，先看蝉妈妈画像
- ❌ 亚马逊数据接入 —— 只做 first mode（TikTok / 抖音 / 天猫）
- ❌ 飞瓜数据接入 —— 不要搞太多数据平台，飞瓜账号交接后仅作备用
- ❌ 移动端适配 —— 只做桌面端
- ❌ 多人实时协作编辑 —— 先用「你出数、他看数改数」模式

#### 本期新增能力

**增量计算（解决「罗盘只给近 30 天」问题）**：

```
每月跑一次全量拉取 → 存上月快照
本月拉取时 → 用本月数据 - 上月快照 → 算出环比增速
```

**筛选器本期新增**：

- 按「数据来源」筛选（罗盘 / 蝉妈妈 / FastMoss / 全部）
- 按「环比增速」排序（升/降）
- 按「突然增量」筛选（增速 > 阈值）

#### 交互

- 点击商品名 → 跳转「商品详情页」（见 C.3）
- 点击「导出 CSV」→ 导出当前筛选结果
- 点击「分来源分榜」→ 按来源拆分成多个子表

### C.4 模块：评论洞察抓取【本期新增】

**定位**：不是独立页面，而是一个后台任务模块，为商品详情页的「第五屏」供数

#### 模块作用

- 从天猫和抖音抓取商品评论
- 清洗、打标、提取关键词
- 为商品详情页提供「好评关键词 / 差评关键词 / 典型评论」

#### 抓取范围

| 平台 | 抓取对象    | 抓取字段                  |
| -- | ------- | --------------------- |

| 抖音 | 商品详情页评论 | 评论内容 / 评分 / 时间 / 用户昵称 |

#### 抓取方式

- **浏览器自动化**：开着浏览器，登录态复用，模拟人工翻页
- **频率**：按需触发（用户在商品详情页点击「抓取评论」），不做定时全量

#### 清洗与打标

- 参考「抓取评论」项目已有的方法论（见 `抓取评论/output/分析报告_v2.html`）
- 硬过滤：剔除广告/水军/官方号
- AI 打标：动机 / 细节丰富度 / 情感倾向
- 关键词提取：好评高频词 / 差评高频词

#### 产出

- `data/comments_<platform>_<product_id>_<date>.json`
- 写入商品详情页的「第五屏」
