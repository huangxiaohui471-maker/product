## 一、选了谁？为什么它最相近

需求本质是：**在一个国家看到的市场信号，能否构成在另一个国家做一款产品的机会**。按「业务形态 / 数据源 / 用户角色 / 产品阶段」四条打分，取交集最高的三个参照物：

| 参照物 | 业务形态 | 数据源 | 用户角色 | 产品阶段 | 相似度 |
|---|---|---|---|---|---|
| **① 亚马逊「商机探测器 Product Opportunity Explorer」** | 平台型选品决策工具 | 站内搜索行为 + 销量 + 评论 | 卖家（选品决策者） | 成熟 | ★★★★★ |
| **② Helium 10 Success Score** | 选品评分模型 | 类目 Top10 商品（销量/价格/上架时长） | 亚马逊卖家 | 成熟 | ★★★★☆ |
| **③ 卖家精灵 Market Health Score™** | 细分类目机会评分 | 关键词库 20 亿条 + ASIN 反查 | 中国跨境卖家 | 成熟 | ★★★★☆ |

**为什么①最相近（逐条说明）**

1. **业务形态相同**：都是「把海量商品数据收敛成少数几个值得深挖的候选」，而不是做全量报表。它的官方表述是**「未被满足的需求（unmet demand）」**——通过消费者搜索行为数据发现**市场空白**。这与本需求的「国内火、国外还没有」在**概念上完全同构**：都是找「需求存在但供给缺位」的缺口。
2. **数据源相同**：都依赖第三方平台取数，且都**拿不到全量精确值**，只能拿榜单/区间/抽样。它同样面对「字段拿不齐」的现实。
3. **用户角色相同**：使用者是**做不做这个品**的决策者（惠子），不是分析师。它输出的是「值得继续研究」而不是「精确市场规模」——这一点直接支持了录音里那句「我不要先把数据凑齐才知道是不是机会」。
4. **产品阶段相近**：我们是在已有工作台上改一个页面，逻辑上对应「在成熟工具上新增一个机会发现视图」。

**②③的价值在于「评分维度」而非「产品形态」**：它们把「机会」拆成了可计算的维度（见第三节），这是我们最缺的部分。

## 二、它们的文档结构长什么样（章节清单）

### 2.1 墨刀 PRD 模板（两套，用于确定**我们 PRD 该怎么写**）

**墨刀标准版 PRD**（`modao.ink/ad/blog/prd-document.html`）：

```
1. 产品概述
   ├─ 产品背景和市场分析（市场环境、竞争对手、市场定位）
   ├─ 目标用户群体及需求痛点（用户画像、需求、痛点）
   └─ 产品的核心价值与定位
2. 功能需求
   ├─ 产品主要功能模块划分 + 相互关系
   ├─ 各功能点详细说明 + 优先级排序
   └─ 交互流程及用户使用路径（进入 → 完成目标的完整流程）
3. 非功能性需求（性能 / 兼容性 / 安全性）
4. 交互及 UI 设计（线框图、流程图、关键界面设计原则）
5. 技术与开发约束（技术栈、第三方 API 依赖、技术挑战与预案）
6. 测试与验收标准（功能测试、关键业务逻辑验证方式、验收标准及上线条件）
```

**墨刀"PRD 模版 A/B"**（by 大莲子 / 小龙，语雀转述版）：

```
1. 产品概述
   ├─ 文档修订历史     ← 记录每次改动
   ├─ 版本说明         ← 各版本核心功能
   ├─ 开发周期         ← 开发/测试/上线 起止日期
   └─ 产品介绍         ← 名称、简介、用户画像、使用场景、定位
2. 流程图
   ├─ 功能结构图       ← 功能模块，展开到用户可见最小单元
   ├─ 信息结构图       ← ★以信息为维度，描述有哪些数据字段
   └─ 任务流程图       ← 用户使用路径、页面及对应关系
3. 功能详情和原型     ← 开发查看频率最高：原型 + 注释（图文互补）
4. 全局说明           ← 设计规范、通用规则
5. 非功能性需求       ← 性能/系统/运营/安全/统计/财务
```

**墨刀敏捷版 PRD**（`modao.ink/ad/blog/agile-prd-template.html`）——**这套对本需求启发最大**：

```
├─ 流程图 / 角色权限 / 名词解释     ← 名词解释用于收录行业术语
├─ 原型页面按迭代期数分文件夹（第 1~N 期）
├─ 原型 + 标注码索引：
│   左边原型上标 A-Z，右边以「一个标注码一行」写需求
│   每行含：序号 / 名称 / 类型（初创·修改·新增·删除，四色区分）/ 需求描述 / 备注
└─ 需求变更对比表                   ← 变更必须留痕
```

### 2.2 竞品的机会模型（用于确定**机会怎么算**）

**Helium 10 Success Score** —— 分析某搜索词下 **Top 10 商品**，三个因子：

| 因子 | 含义 | 作用 |
|---|---|---|
| Market Maturity（市场成熟度） | Top 榜商品已卖多久 | 成熟市场更难进；**新市场可能意味着更容易进入** |
| Average Monthly Sales（平均月销） | Top10 平均销量 | 销量高 = 需求强 |
| Average Product Price（平均价格） | Top10 平均价格 | 影响利润与竞争强度 |

- 判定：**≥7 分（满分 10）视为好机会**
- 配套 **Two-Factor 筛选**：设定「最低月营收 + 最高评论数」双阈值，用勾选数（1~4 个）表示 Top10 中满足条件的商品数 → 判断竞争强度
- **它自己写明了一句关键话**：「Success Score 不判断整体赛道潜力，只判断**用一款新品打进该赛道头部有多容易**」

**卖家精灵 Market Health Score™**：**得分 ≥7.5（满分 10）的品类，失败率降至 18% 以下**。四步闭环：关键词挖掘 → 竞品分析 → 市场评估 → 机会识别。关键阈值：月均搜索量 ≥3 万次、BSR 中位数 ≤5,000、**评论增长率 ≤15%/月**、毛利率 ≥35%。

**业界通用四层加权算法架构**（Jungle Scout / Helium 10 / 卖家精灵 / 鸥鹭 共同结构）：

| 层 | 内容 | 权重参考 |
|---|---|---|
| 第一层 · 平台基础数据 | 类目销量（件/月）、BSR 排名、**Review 增长速率** | — |
| 第二层 · 竞争分析 | **月新增竞品数 / 类目总卖家数**（健康阈值 ≤3.7%） | — |
| 第三层 · 利润模型 | 运费、佣金、VAT/关税、广告 ACoS 历史均值 | — |
| 第四层 · **趋势校准** | **Google Trends 区域搜索指数**、海关 HS 编码出口量同比、社交媒体声量周环比 | Google Trends **18%±3%** |

**亚马逊商机探测器的输出内容**（= 它认为一个机会该带哪些证据）：市场趋势、热门产品特征、客户评价分析、客户群体画像、搜索趋势、价格洞察。

## 三、哪些结构值得照搬

| # | 照搬什么 | 落到我们哪 |
|---|---|---|
| 1 | **名词解释**（墨刀敏捷版） | PRD 开头定义「信号 / 候选机会 / 证据链 / 门槛 / 判定」——这些词现在团队各说各话 |
| 2 | **信息结构图**（墨刀模版A/B）——以信息为维度列全部数据字段 | 直接对应 PRD 的「字段与数据源映射」表 |
| 3 | **文档修订历史 + 版本说明** | 现有 `PRD_v1.0.md` 有版本号但没有修订历史表，本次补上 |
| 4 | **标注码索引（原型 A-Z ↔ 需求逐行）** | 线框图里给每个区块标 A/B/C…，PRD 逐行对应，避免"图说图、文说文" |
| 5 | **Top-N 抽样 + 门槛判定，而非全量精确值**（Helium 10） | 现有代码死磕"全量精确增速"，改成"Top-N 候选 + 门槛" |
| 6 | **「不判断整体潜力，只判断可进入程度」的自我约束**（Helium 10 原文） | 直接对应录音里那句「AI 的任务不是证明这是好机会，而是弄清它到底成不成立」——必须写进 PRD 作为设计原则 |
| 7 | **双因子阈值 + 勾选数**（Helium 10 Two-Factor） | 我们改成"多维信号命中数（N/M）"，比单一分数更可解释 |
| 8 | **市场成熟度 = 上架时长**（Helium 10） | 对应"增长很快的新品"：用**上市日期**算品龄，而不是只看增速 |
| 9 | **趋势校准层**（业界四层架构） | 印证"不能只拿增速判断"——增速只是第三/四层的一个因子 |
| 10 | **需求变更对比表**（墨刀敏捷版） | 冻结 v1.1 后改需求必须走变更单 |

## 四、哪些字段口径可复用 / 哪些不适用

### 4.1 可直接复用

| 字段 / 口径 | 来源 | 我们能否拿到 | 说明 |
|---|---|---|---|
| BSR / 榜单排名 | Amazon / 罗盘 / FastMoss | ✅ 已有 `榜单排名`、`名次变化` | 直接复用 |
| Review 数量 | Amazon | ⚠️ 仅 FastMoss 有 `评价数`（289 条） | 中国侧（罗盘/蝉妈妈）**无** |
| 评分（星级） | Amazon | ⚠️ 仅 FastMoss 有 `评分` | 同上 |
| 上架时长 → 品龄 | 各平台 `launch_date` | ⚠️ FastMoss 有、蝉妈妈有（50 条）；**抖音罗盘 0/100** | 需注明缺口 |
| 平均价格 | Amazon | ✅ 罗盘/蝉妈妈/FastMoss 部分有 `价格` | 罗盘 60/100、蝉妈妈 0/50 |
| 评论增长速率 | Amazon | ❌ 无历史快照 | 需多期采集才能算，本期不做 |
| 月新增竞品数/总卖家数 | Amazon | ❌ 无 | 本期不做 |

### 4.2 **不适用**（照搬会出错，必须说明原因）

| 字段 / 口径 | 为什么不适用 |
|---|---|
| **利润率 / FBA 费用 / ACoS 阈值（≥35%、≥25%）** | 这些是**亚马逊 FBA**口径。我们做的是抖音电商 + TikTok Shop，费用结构完全不同（达人佣金、投流、货架）。且本地库 `预估成本` 只有 40 条，**不足以算利润**。本期不引入利润维度。 |
| **Google Trends 区域搜索指数（权重 18%）** | 该口径衡量**搜索意图**；我们的数据源（罗盘/FastMoss）给的是**成交**。两者混算会互相污染。且我们拿不到稳定的 Trends API。**明确不引入**。 |
| **月均搜索量 ≥3 万次** | 我们没有关键词搜索量数据源。**不引入**。 |
| **海关 HS 编码出口量** | 属外贸口径，与美妆选品决策不匹配，且无数据。**不引入**。 |
| **「≥7 分就是好机会」这类单一总分** | **与本次需求的核心诉求直接冲突**。用户要的是"多维判断 + 说清为什么"，不是一个不可解释的总分。**我们改用「多维信号命中 + 逐条证据 + 判定档位」**。 |
| **Amazon 专属的类目/BSR 体系** | 我们的类目体系是自建的「品类 → 二级类目 → 三级类目」，不能直接用 Amazon 节点。 |

### 4.3 「新包材」这个维度的口径（业界怎么定义）

调研到 2026 美妆包装趋势的**公认趋势清单**，可作为我们的"形态/包材"关键词词典：

| 趋势 | 含义 | 为什么重要（原文观点） |
|---|---|---|
| Refillable / 替换装 | 外壳耐用 + 替换芯 | 支撑复购与溢价 |
| Mono-material 单一材质 | 瓶身/泵头/盖同材质，免拆解回收 | 2026 主流 |
| PCR 再生材料 | 30%~100% 消费后再生料 | 品牌 KPI |
| Airless 真空泵 | 隔绝空气，防活性物氧化 | 从高端走向主流 |
| 精准涂抹器 | 滚珠头、针管头、按摩头、气垫泵 | 提升使用仪式感 |
| 智能包装 | QR / NFC / RFID | 溯源与复购入口 |
| 轻量化奢华 | 薄壁玻璃、阳极氧化铝盖 | 兼顾手感与运费 |
| 便携形态 | 链挂唇釉、精华棒（serum stick） | 社交电商适配 |
| 无水剂型 | 粉 / 浓缩片 / 次抛 | 单剂量无菌 |
| 柔性软管 | 单一材质 PE 软管替代铝塑复合管 | 跨境柔性包装订单青睐 |

**关键原文观点（值得写进我们的设计原则）**：
> "Packaging Must Sell Before the Formula Speaks" —— 商品首次出现在 TikTok 视频/直播/商城图里时，**包装只有几秒钟说明价值**。包装不再只是装饰，而是**产品体验的一部分**。
> 竞品分析框架给出的三色门槛：评论数（<1,000 绿 / 1,000-10,000 黄 / >10,000 红）、价格带跨度（>25% 绿 / 10-25% 黄 / <10% 红）、评分质量（一致好评但可修补=黄）、品牌多样性（分散无头部=绿）。

## 五、它们做得不好的地方 / 我们要补什么

| # | 它的缺陷 | 我们要补上什么 |
|---|---|---|
| 1 | **只判"能不能打进"，不判"这个需求真不真实"**（Helium 10 明确自我限定） | 我们要**两端都判**：①市场上出现了什么信号 ②这家企业能不能做——对应录音里「机会需要连接两端」 |
| 2 | **输出一个不可解释的总分**（7/10、7.5/10） | 我们输出**可追溯的信号清单 + 每条信号的原始记录**，点开能看到是哪条商品、哪个字段触发的（用户明确要求"可追溯到原始数据"） |
| 3 | **幸存者偏差**（原文原话：Ecomhunt 这类工具"展示的是已经赢了的产品，等你去采购上架，窗口可能已经变窄"） | 我们必须显式暴露**机会窗口**：上架多久了、名次在升还是在掉，而不是只展示"现在已经很火" |
| 4 | **不处理"数据拿不到"** | 我们的现实是：抖音罗盘**环比增速 0/100、上市日期 0/100**；美国 FastMoss **真实数据只有 14 条**。必须把「证据不足」做成**一等公民的结论**，而不是隐藏或补零（录音里明确："未知不当作 0") |
| 5 | **不做跨市场空白检测** | 这是本需求的**独有增量**：没有任何一个对标产品做"中国 ↔ 美国"的供给缺口对照。我们要靠**品类 × 形态/成分**做可比映射，而不是靠商品名精确匹配 |
| 6 | 均为**英文/亚马逊语境**，公式（FBA、关税、ACoS）不适用国内抖音电商 | 双 Tab 分别用各自市场的口径，**不强行统一**：中国侧用抖音罗盘（+蝉妈妈补增速），美国侧用 FastMoss |
