五真正可复用的做法

下面 14 条是这两天花掉的代价换来的，不是通用建议。每条都配有当时的实证。

取数与验证

  1. 端点真伪双测法。「无意义词返回 0 条」且「不同关键词返回不同结果」两条都过才算真。只测一条会被 mock 骗——官方 mock 字段结构完整、毫无破绽。实证：/douyin/search/* 搜「健身」返回猫咪账号，整套接口作废。
  2. 不可信端点写进脚本常量。做成 NOT_USABLE 注释块，让脚本永远不可能调用它。比写在文档里「记得别用」可靠得多。
  3. 先验鉴权范围，再花额度。拿到 key 先打一次零成本端点看 scope 与余额，确认目标路径在授权内，再开始批量。
  4. 字段找不到时，先怀疑路径，别怀疑限流。那条「隐性频率限制」结论整整误导了一轮，真相只是少读了外层一层 data。改成 1.5 秒间隔后 100% 成功——所谓限流根本不存在。
  5. 用最小复现拆开误导性报错。extract_audio 报「音轨提取失败」，实际 ffprobe 显示 aac 音轨健在，真因是编码写死 pcm 却按 .m4a 后缀输出。做法：pcm 写 .m4a 失败 / pcm 写 .wav 成功，一次对照就定性。
  6. 渲染后的页面也是数据源。请求体加密（蝉妈妈）或接口缺签名（FastMoss 需 cnonce）时，别硬刚接口——读 /promotionRank/ 渲染后的表格更快。

判读与口径

  1. 榜单要分两层看。第一层是内容池聚合出的「谁在起量」，第二层是深挖后的「这到底是什么号」。实测榜首常是萌娃号/情绪号/AI 动画号，美妆占比仅 4%~15%——只有 beauty_share 才能回答「该不该抄」。
  2. 排序口径必须匹配数据形状。一次搜索只回一页 → 同账号出现 1–2 次没有区分度 → 账号榜必须按「代表作分数」排。按条数排的初版把 23 万赞的爆款号压到了普通号后面。
  3. 平台自己的产出是最便宜的校验集。译名不硬编：拿榜单里 66 条平台原生中文类目路径反向校验 AI 译名，66/66 才入库；再用官方三级 cid 反查中文类目，230 条一致 223 = 97%。
  4. 不做推测，空值要分类。成分只抽显性成分词，命中为空必须区分「没人用它」和「标题没写」；海外记录销售额一律显示「—」，不拿 0 冒充；平台没写的备案号留空，不填「无」。
  5. 降级要诚实且点名。引擎体检逐条标「可算 / 缺字段」并点名哪个市场一条都参与不了。这比让规则静默返回 0 条、让人以为「没机会」要好得多。
  6. 极端值不进展示层。低基数新品（印尼唇妆 +57725%）会把整格均值拉到 +8273%。列表与 Hero 用中位数、KPI 用截尾均值，只改显示不改规则判定——规则要不要跟着改是你的决定，不替你做。
  7. 诊断面板不要删。看板「数据通路体检 + 覆盖度热力格」、洞察「引擎体检」、空态「三分解诊断」——空格的格子本身就是结论。

工程与协作

  1. 同源单一 + 单向重绘。页面 = 通用引擎 + 配置；唯一刷新入口 refreshAll()，渲染函数之间严禁互调（防递归）。离线种子必须「云表 → 种子」单向注入，反向手工维护必然漂移。口径文档的字段清单从 HTML 的 FIELDS 数组正则抽取，文档与产品同源。
外加一条工具级纪律（已写进记忆）：同一条消息里对同一个文件并行发多个编辑会互相覆盖——后一个基于旧内容写回，前一个静默丢失。本轮因此丢过两处改动，靠关键词在位性校验才发现，肉眼看 diff 很难注意到「少了一行」。同文件串行、跨文件才并行。

A · 通道与端点（14 条）

A1抖音搜索接口返回固定演示数据

现象：/douyin/search/* 搜护肤、宠物、健身返回同一批猫咪账号。根因：官方 mock，字段结构完整无破绽。 修法：双测判假 → 写进 NOT_USABLE，永不调用。

A2TikTok 商品搜索报 422

根因：参数名是 search_word，不是 keyword。

A3中文关键词在非中文区无效

现象：搜「护肤精华」返回 Pomade / cream。修法：商品与内容两侧都必须英文词，各建一份英文词表。

A4TikTok 搜索 ID 与 GB 恒 0 条

根因：服务端覆盖缺口，不是词的问题 （serum / moisturizer 结果一样）。可用区实为 US/TH/VN/MY/PH/SG/JP。

A5TikTok 传了 region 仍混入其他国家

现象：指定 US 也混进 PH/CA/GB（实测 US 占 59/120）。根因：region 是排序倾向不是过滤器。 修法：报告里如实给出真实地区分布，不假装全是美国。

A6商品详情报「商品不存在」

根因：fetch_product_detail_v3 必须传该商品所属 region。 且详情区与搜索区是两个集合（US/ID/VN/MY/TH/PH/JP）。

A7详情取到的都是空组件

现象：19 个组件 18 个空壳，误判成限流并把间隔调到 45 秒。根因：主数据在两层 data 之下（data.product_data.page_config.components_map），代码只读了 root['product_data']。 修法：修正后 1.5 秒 100% 成功 → 旧「限频」结论作废。

A8店铺与类目读成 None

根因：shop_info / category_info 是 product_info 的兄弟节点，不是子节点。

A9详情取不到价格

根因：价格在 promotion_model.promotion_product_price.skus_price，skus 数组里没有价格字段。

A10TikTok 内容搜索返回空列表

根因：列表在 data.search_item_list，不是 data.aweme_list（后者恒为空数组）。

A11小红书互动量全读成 0

现象：两条都踩——item 顶层 id 恒为 None（真 id 在 note.id）；note.liked 是「我是否收藏过」的布尔值，点赞数叫 liked_count。

A12蝉妈妈榜单接口抓不到

根因：POST /v6/product/search 请求体加密。 修法：改读 /promotionRank/ 渲染后的表格（50 行/页）。 附带两条：品类筛选 URL 参数无效，必须模拟点击品类文本；品类树字段名是 label 不是 name。

A13webbridge 返回 502

根因：动作名写错返回的是 502，不是 404。 修法：用 list_tabs 探活。 另：evaluate 打的是「最后聚焦的标签」，多平台任务每次都要先 find_tab，否则静默打到上一个平台。

A14FastMoss 榜单接口即使带 cookie 也被拒

根因：返回 MSG_SAFE_0001，缺 cnonce 签名。 游客态还有两个附加限制：只给前 2 页、l1_cid 被忽略 → 必须本地按一级类目过滤，否则食品饮料/汽车/女装会污染选品库。

B · 数据口径与判读（8 条）

B1均值被低基数新品拉爆

现象：印尼一条唇妆环比 +57725%，把「市场机会」整格均值拉到 +8273%，Hero 首版就显示了这串鬼数字。修法：列表/Hero 用中位数，KPI 用截尾均值（去两端各 10%），只改显示不改规则。

B267 赞的小号排到第一

根因：官方 isLowFansButHot 标记不等于真跑出来了（71 赞也标）；且池内出现次数权重过高，会让刷量号（13 条均赞 369）挤掉真爆款。修法：加质量门槛 + 粉丝量级分档 + 同档比较。

B3榜单第一名不是美妆号

现象：榜首「一只猪」1.6 万粉拿 15 万赞，实为亲子号。修法：deep() 算 beauty_share 做定性，落成 verdict 字段。

B4关键词误命中，捞出无关内容

现象：搜「抗老」捞出「电动踏板硬抗老外暴力测试」；搜「胶原蛋白」捞出「砂锅猪蹄」。根因：item_query 本质是挂了商品的带货视频库，剧情号会因挂车被带入。 修法：MAKEUP_LEXICON 强美妆词表过滤，滤掉 1932/23233 条。

B5评论热词榜全是虚词

现象：前列是「是我 / 一点 / 真的」。修法：COMMENT_STOP_WORDS 停用词表。

B6成分/概念榜所有条一样长

根因：按「出现频次」排，而标签稀疏。 修法：改按「承载商品销售额合计」排。

B7洞察规则在真实数据上一条都不命中

根因：窗口期阈值 ≤15 是示例量纲（真实上升品关联达人数中位 110）；退货率三个平台榜单都不给。 修法：窗口期去掉达人/销售额门槛只看环比（命中 0 → 56 条）；改良机会与风险提醒改差评关键词驱动。

B8示例数据在骗人

现象：韩国 7 条被错标成 FastMoss（FastMoss 不覆盖韩国），且带着销量/销售额/环比。修法：改标 Hwahae/Olive Young 并清空不可得字段，榜单排名从「TikTok 韩国个护第 7」改为「화해 身体护理榜第 7」。

C · 云表与页面（12 条）

C1写入报「校验后为空，无有效字段」

根因：值必须包装——{number:199} / {select:"护肤"} / {text:"…"} / {date:"…"}，写扁平值被拒。

C2建 select 字段成功，之后所有写入全失败

现象：报 duplicate select option text: text=""。根因：选项键是 text 不是 name，用 name 会静默建出 N 个空选项，建字段当时不报错。修法：改回时用 update_database_field --field-id 并保留原 option id，否则存量单元格被清空。

C3字段加了但写不进

根因：property.config 顶层必须带类型键（{"select":{"options":[…]}}），写 {"options":[…]} 被拒。

C4批量改记录后人工字段丢失

根因：删了重写会换 record_id。 修法：一律按 record_id 原位 update，单次 ≤100。

C5查询静默返回 0 条

根因：db.query 失败时 stdout 是 {"error":…} 且不抛异常。 修法：必须判 results is not None 并重试；单次一页、pageSize ≤200、startCursor 续页。

C6第二张云表读不出来

根因：光有 data-sp-database-id 绑定标注不够，还必须 page_database_relation.py --action link 显式关联。

C7lint 报 DSDK002 / 008 / 012

002 需硬编码 var DATABASE_ID（只写 DB.product.databaseId 不行）；008 有 addRecord 就必须有 localStorage 三件套；012 渲染云表数据的元素要成对绑定。另：lint 只吃一份 schema，多表页要把 properties 合并。

C8批量脚本跑一半全变 NETWORK_ERROR

根因：op_... token 有效期 30 分钟，过期后表现得像网络故障。 修法：批量要在一次进程里跑完。

C9上传页面卡在超时

现象：curl --noproxy '*' 报 (56) Recv failure: Operation timed out。修法：上传类请求去掉 --noproxy 走代理，0.3 秒 200。 注意与「本机回环要加 --noproxy」策略相反——别一概而论。

C10开事务报 node not found

根因：用了内层 node id。 修法：用外层 lMO9EIAM8o5cIwqudwUDr1。

C11拿本地文件覆盖线上页面

根因：线上 index.html 带平台注入的 data-page-node-id / <!--pnid:--> / inject.js，且平台会重排属性顺序。 修法：只比语义不比字节，用 sem_diff / sem_verify 剥掉注入属性后比对。

C12本地打开显示「离线模式」，以为坏了

根因：ONLINE = !!(window.__SMART_PAGE__ && window.__SMART_PAGE__.database)，file:// 与 127.0.0.1 天然为 false → 退 localStorage。 不是故障、不是断网、不是没接入。已加 envLabel / IS_LOCAL 明确区分，并在本地版给「打开线上版」按钮。

D · 工具环境与流程（6 条）

D1下载 tesseract 连续失败约 40 次

根因：官方 releases 的 assets 数量 = 0，从不发 macOS 预编译包——那个文件在任何下载器上都是 404，换浏览器换工具都一样。修法：下大文件前先打 api.github.com/…/releases/tags/<tag> 看 assets 是否存在；连续失败两次就停下来验前提，不要换姿势重试。

D2grep 静默返回 0 命中

根因：macOS BSD grep 不支持 BRE 的 \| 交替（不只是 -P 不可用），grep -rn "a\|b" 会返回 0 命中 + exit 1，看起来像「扫干净了」。修法：多分支一律 grep -E 或直接用 Grep 工具。

D3Node 脚本打印 NaN 且不报错

根因：混用了 Python 风格 % 格式化——'%d' % n 在 JS 里是取模。修法：统一模板字符串。 这个坑把「哪个视图出错」的输出整条吞掉了两次。

D4抽帧报 Error muxing a packet

现象：看着像源文件损坏。根因：ffmpeg 不自动创建输出目录。 修法：先 mkdir -p。

D5编译 Swift 报 unable to load standard library

修法：编译必须显式给 -sdk /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk。 另外：误删过 ~/.workbuddy/binaries/tools/src/（含 Swift 源码），已重建并重新编译——这个目录要当作源码看待，不是残渣。

D6同文件并行编辑丢改动

根因：同一条消息里对同一文件发多个编辑，后一个基于旧内容写回。 修法：同文件串行、跨文件才并行；改完用关键词在位性校验，别只看 diff。 本轮丢了 SKILL.md 一行表格 + tools.md 一句措辞。另有两条相关：/tmp 会被清理，交付物必须落工作区；GBK 文件名的 zip 要 cp437 → gbk 解码后再解压。
